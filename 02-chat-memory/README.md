# Этап 2 — Память диалога

## Цели

- Удерживать контекст диалога между запросами
- Понять разницу между ограничением по сообщениям и по токенам
- Сохранять историю в персистентное хранилище
- Изолировать память по пользователю/сессии

## Ключевые концепции

| Концепция | Назначение |
|-----------|-----------|
| `ChatMemory` | абстракция памяти диалога |
| `MessageWindowChatMemory` | хранит N последних сообщений |
| `TokenWindowChatMemory` | хранит сообщения, пока влезают в M токенов |
| `ChatMemoryStore` | persistence backend (Redis/Postgres/в памяти) |
| `memoryId` | идентификатор сессии/пользователя |

## Что строим

1. Простой консольный диалог с `MessageWindowChatMemory(10)`
2. Свой `ChatMemoryStore` поверх Map
3. Свой `ChatMemoryStore` поверх Redis (опционально)
4. Многопользовательский режим: разный `memoryId` → разные истории
