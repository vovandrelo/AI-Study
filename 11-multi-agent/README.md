# Этап 11 — Мультиагентные системы

## Цели

- Скоординировать несколько специализированных агентов под одну цель
- Освоить три ключевых топологии и понять их компромиссы
- Использовать общий state в LangGraph как «общий рабочий стол» агентов

## Топологии

### Supervisor
```
              ┌──────────┐
              │ supervisor │
              └─────┬──────┘
       ┌────────────┼────────────┐
       ▼            ▼            ▼
 researcher       coder        critic
```
Supervisor выбирает следующего исполнителя по состоянию. Гибкий, но дороже (лишний LLM-вызов на роутинг).

### Pipeline
```
researcher → writer → editor → END
```
Жёсткий порядок. Дёшево и предсказуемо, не подойдёт для нелинейных задач.

### Debate
```
proponent_A ↘
              judge → END
proponent_B ↗
```
Два агента отстаивают разные позиции, judge выносит вердикт. Хорош для качественных решений (архитектура, стратегия).

## Что строим

1. Supervisor для разработки фичи: researcher (читает доки) → coder (пишет код) → critic (ревью) → coder (правит).
2. Pipeline для статьи: researcher → outline → writer → editor.
3. Debate для архитектурного выбора: «monolith vs microservices» — два агента-адвоката и judge.

Все три варианта — на одном `StateGraph` с разной топологией рёбер.
